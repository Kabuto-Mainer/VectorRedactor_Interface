# Использование строк для идентификатора ресурса в рендере

Для идентификации текстур, видео и прочих ресурсов - только отдельный ResourceID. 
Поиск каждой текстуры в каждом кадре - вещь долгая + не очень необходимая.

Хранить ResourceID сильно проще + в любом случае где-то идентификатор ресурса будет сохраняться - поэтому практичнее использовать ID.

# Какие примитивы необходимы в UIManager? (Кнопки, окна, пулы(массив кнопок))

Считаю необходимыми следующие примитивы:
- Обычная кнопка с 3 положениями. Действие задается только при нажатии
- Кнопка переключатель с 2 положениями. Действие задается и на включение, и на выключение.
- Кнопка с контекстным меню. Имеет 2 положения. При нажатии создает контекстное окно с соответствующими кнопками.
- Контекстное окно. Саморасширяющийся пул из кнопок. Расположение строго вертикально.
- Стандартное окно с возможность закрытия и переноса.
- Обычный пул кнопок. Может располагаться как по вертикале, так и по горизонтали. Занимает сразу все место. Не занятое место оставляет пустым. 
- Просто контейнер из объектов. Есть варианты с задним фоном и без него.

# Как задавать настройку создаваемых окон? Через JSON конфигурацию или через бинарный формат(какая то структура)

JSON формат упирается в настройку команд для кнопок и парсер в runtime.
Практичнее использовать структуру, задающую описание.
По ней и по примитивам добавляется отдельный большой вопрос.

# Как будет организована модальность? Через `run` или стек из укыазателей на модальное окно.

Стек из указателей на модальное окно.
Проблема рендера модального окна поверх всего решаема - просто в конце еще раз вызывается метод draw от текущего рендера.
Но это порождает другую проблему - при отсутствии модального окно весь рендер будет перерисовываться дважды.
Разумеется, можно хранить где-то указатель на модальное окно, но тогда при смене окна обратно его придется перезаписывать. 
Как мне кажется, схема со стеком решает большую часть проблем, добавляя единственность цикла обработки.


# Новые вопросы|проблемы с UI

Мне пришла идея реализации окно в UI.
Окно делиться на сетку, при этом размеры каждой строки и столбца могут быть 2 типов: фиксированного размера и плавающего размера, где имеет значение вес.
В каждой ячейке соответственно может быть либо другая сетка, либо еще один контейнер, либо виждет.
Если есть вопросы по этой концепции - сразу задавайте.
